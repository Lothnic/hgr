# HGR Project Cleanup Analysis

## Project Overview

Two-stage MT pipeline: mT5-large + LoRA SFT → DPO/HGR training on low-resource language pairs (kangri↔hindi). 25,541 raw pairs, ~21k after cleaning. Best Stage1 result: BLEU 24.31 (decode-tuned), best DPO-only: BLEU 5.44 (sample benchmark), best DPO full-data same-protocol: BLEU 22.36.

## Current State

33 files including 10 Modal scripts, 9 autoresearch/log artifacts, 2 output reports, 4 debug stubs, 3 broken evaluation scripts, and 1 stale generated data file — all need removal. That's 29 of 33 files going away.

## KNOWN ISSUES IN KEPT CODE

1. **`combined.py`** has a bug on line ~200: `src_inputs` is used before assignment in the HGR loss block (referenced at `src_inputs.input_ids` but never set — the case that sets it was removed during the reward refactor). It also still imports from `SentenceTransformer` even though `create_reward_function` handles it. Needs fixing during reimplementation.

2. **`main.py`** `prepare-data` and `gen-unpreferred` commands load from `prepare.py` which uses `facebook/m2m100_418M` for unpreferred generation when actually `prepare.py`'s `generate_unpreferred` should use the Stage1 PEFT model.

3. **`local_stage2_data.py`** is a decent template but hardcodes paths (`stage1_output/`, `stage2_output/`), sample sizes, and uses `hgr-stage1` volume. Needs path restructuring for local GPU.

4. **`pyproject.toml`** has `bitsandbytes` dependency (quantization) and `trl` (DPO via library) — both remain useful for local GPU training. Modal-specific deps are already absent — good.

5. **Training scripts reference `google/mt5-large`** throughout. On local GPU, you may want `google/mt5-base` or `google/mt5-small` depending on VRAM. The `TrainingConfig` class makes this easy to change.
